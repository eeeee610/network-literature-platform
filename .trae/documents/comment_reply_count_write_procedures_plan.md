# Context

当前 `comment.reply_count` 由业务在评论操作后显式调用 `sp_sync_comment_reply_count` 重算，容易漏调用或重复调用。目标是让回复数随评论写操作自动、同事务维护，并保证仅回复自身从不可展示变为可展示时 `+1`、反向变化时 `-1`。

已确认 MySQL 1442 禁止 `comment` 自表触发器直接更新 `comment`，用户已选择“统一写入过程”方案，不采用操作表触发器或拆分评论/回复表。不得修改冻结数据字典字段。

## 已确认口径

- 回复自身可展示：`parent_id IS NOT NULL AND audit_status = 1 AND status = 1`。
- 状态保持现有定义：`status` 为 1 正常、2 隐藏、3 已删除；`audit_status` 为 0 待审核、1 通过、2 驳回。
- 父评论可展示性是 `v_comment_visible` 的额外在线展示条件，不进入 `reply_count` 公式。父评论隐藏/恢复不级联修改子回复或计数；恢复后子回复按自身状态重新展示。
- 删除采用现有软删除 `status=3`，不物理删除评论记录。
- 现有 `trg_comment_bu` 在内容变化时将 `audit_status` 置 0，写入过程必须在 UPDATE 后重读实际状态，不能自行推测 NEW 状态。

## 实现步骤

### 1. 增加统一评论写入过程

仅修改 `sql/objects/C_互动与榜单_视图与存储过程_v1.0_20261121.sql`，新增：

- `sp_create_comment`：新增一级评论或回复，初始待审核；回复初始不计数。
- `sp_edit_comment_content`：修改内容，兼容现有重新送审触发器。
- `sp_audit_comment`：审核通过、驳回或置回待审核。
- `sp_set_comment_status`：正常、隐藏、恢复、软删除。
- `sp_move_comment_parent`：修改父评论，支持可见回复跨父移动。
- 私有辅助过程 `sp_apply_comment_reply_delta`：接收 OLD/NEW 的 `parent_id、status、audit_status`，只处理当前评论对其父评论的贡献。

保留 `sp_sync_comment_reply_count`，但仅作为后台对账/修复工具，正常业务过程和业务接口不得调用它维护每次操作。

### 2. 精确状态迁移

辅助过程按以下规则增量更新：

| 变化 | 旧父 | 新父 |
|---|---:|---:|
| 同父，不可展示 → 可展示 | 不变 | +1 |
| 同父，可展示 → 不可展示 | -1 | 不变 |
| 可展示状态跨父移动 | -1 | +1 |
| 不可展示状态跨父移动 | 不变 | 不变 |
| 同父重复更新、可见性不变 | 不变 | 不变 |
| 回复变为一级评论 | 旧可见时 -1 | 不适用 |
| 一级评论变为可见回复 | 不适用 | +1 |

减计数不使用 `GREATEST` 掩盖异常，沿用 `reply_count >= 0` CHECK 发现计数不一致。除上述迁移外不执行计数 UPDATE。

### 3. 事务、锁与写入边界

- 每个入口独立 `START TRANSACTION`，异常时 `ROLLBACK` 并 `RESIGNAL`，评论操作和计数更新必须同时成功或失败。
- 更新/移动前以 `FOR UPDATE` 锁定目标评论并保存 OLD；涉及两个父评论时按 `comment_id` 升序锁定，降低死锁概率。
- UPDATE 后重读实际 NEW，再调用增量辅助过程；新增时验证并锁定父评论。
- 父评论变更需验证父评论存在且不能指向自身；不允许通过直接 SQL 绕过入口。
- 部署文档明确：应用账号收回 `comment` 直接 INSERT/UPDATE/DELETE 权限，只授予对应写入过程 EXECUTE；辅助过程和修复过程不向普通应用账号授权。

### 4. 保留现有结构

- 不修改 `comment` 表结构、字段、CHECK、索引或数据字典。
- 不修改 `v_comment_visible` 的父评论过滤逻辑。
- 保留 `trg_comment_bu`；只更新 `sql/objects/C_互动与榜单_触发器_v1.0_20261121.sql` 的设计说明，不再描述为业务显式调用同步过程。

## 测试与验证

修改 `test/C_互动与榜单_测试数据_v1.0_20261121.sql`，正常操作不再调用 `sp_sync_comment_reply_count`，覆盖：

1. 新增待审核回复：计数不变。
2. 审核通过：`+1`；重复通过：不变。
3. 审核驳回：可见时 `-1`；重复驳回：不变。
4. 隐藏：可见时 `-1`；重复隐藏：不变；恢复：`+1`。
5. 软删除：可见时 `-1`；重复删除：不变。
6. 可见回复跨父移动：旧父 `-1`、新父 `+1`；同父重复移动及不可见回复移动：不变。
7. 可见回复内容修改：触发器置待审核并 `-1`，重新通过后 `+1`。
8. 父评论隐藏：视图不展示其子回复，但 `reply_count` 不变；父评论恢复后回复按自身状态重新展示。
9. 非法操作导致异常时，评论状态和计数均回滚。
10. 测试末仅以对账目的调用 `sp_sync_comment_reply_count`，验证增量结果与全量重算一致。
