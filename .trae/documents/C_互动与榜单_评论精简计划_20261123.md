# C 互动与榜单：评论模块精简计划

## Context

当前评论实现包含递归祖先、任意层级、父评论移动、独立数据库权限和过程内部事务，超出课程设计所需范围。本次目标是在不新增表、不增加业务功能、不删减评分与榜单的前提下，将评论收敛为“一级评论 + 直接回复”，统一由调用方管理事务，并保留审核、重新审核、审核日志及必要的计数一致性。

## 一、计划删除

### 文件

- 删除 `sql/objects/C_互动与榜单_权限_v1.0_20261123.sql` 整个文件，不再维护 `nlp_app`、GRANT/REVOKE、角色或列级权限检查。

### 数据库对象与测试内容

- 删除 `sp_move_comment_parent` 的过程定义；对象脚本中保留 `DROP PROCEDURE IF EXISTS` 以清理已部署旧对象。
- 删除 `sp_apply_comment_reply_delta` 中跨父迁移、双父加锁等只因移动父级而存在的分支。
- 从测试前置中删除 `nlp_app@localhost` 的 DROP/CREATE USER。
- 从测试脚本中删除 `sp_test_move_parent_failure`、移动父级、循环引用、孙级回复及数据库应用账号权限测试。
- 从文档和执行结果中删除上述已移除功能的交付说明，不保留为现行接口。

## 二、计划保留

- `sql/ddl/C_互动与榜单_建表_v1.0_20261121.sql`：6 张表、字段、外键和 CHECK 均不改，包括 `comment.parent_id`、`comment.reply_count`。
- 8 个现有触发器的逻辑不变，保留点赞计数、评论内容修改重新送审、评分短重重审和评分统计。
- 保留 `v_novel_rating_summary`、`v_ranking_item_detail`、`v_ranking_latest`。
- 保留 `sp_create_comment`、`sp_edit_comment_content`、`sp_audit_comment`、`sp_set_comment_status`。
- 保留 `sp_apply_comment_reply_delta` 的同父 OLD/NEW 状态迁移计数，以及 `sp_sync_comment_reply_count` 的对账/修复用途；不扩展新计数机制。
- 保留 `sp_refresh_rating_stat`、`sp_generate_ranking`、`sp_get_ranking` 及收藏、评分、打赏、销售榜单口径。
- 保留 D 模块 `audit_log` 及其 COMMENT 审核目标关系，不修改 D 建表脚本。
- 精简后仍为 4 个视图，正式存储过程由 10 个减为 9 个。

## 三、计划修改

### 1. `sql/objects/C_互动与榜单_视图与存储过程_v1.0_20261121.sql`

- `v_comment_visible`：改为非递归查询。评论自身须 `status=1 AND audit_status=1`；直接回复还要求其一级父评论同时满足该条件。一级不可见时其回复不展示，记录保留。
- `sp_create_comment`：
  - `parent_id IS NULL` 创建一级评论；非 NULL 时要求父评论存在且父评论自身 `parent_id IS NULL`，拒绝回复直接回复。
  - 回复与父评论的 `novel_id`、`chapter_id` 严格一致，继续使用 NULL 安全比较。
  - 一级评论及回复均校验非 NULL 章节确实存在且属于传入小说，修复一级评论跨小说归属缺口。
- `sp_edit_comment_content`、`sp_audit_comment`、`sp_set_comment_status`：保留现有校验、锁行、重审和计数行为，删除 `START TRANSACTION`、`COMMIT` 及仅用于内部 ROLLBACK 的异常处理器。
- `sp_generate_ranking`：保留榜单业务及临时表清理，删除内部事务开始、提交和回滚；DELETE + INSERT 是否整体提交由调用方事务保证。
- 删除评论过程中的显式 `SQL SECURITY DEFINER` 及权限部署说明，不新增专用账号或安全配置。

### 2. `sql/objects/C_互动与榜单_触发器_v1.0_20261121.sql`

- 仅更新设计注释：删除父评论移动、独立内部事务等过时描述，说明计数由写入过程在调用方事务中维护。
- 不修改任何触发器逻辑。

### 3. `test/C_互动与榜单_测试前置_v1.0_20261121.sql`

- 删除测试应用账号；保留测试库及 A/B 模块最小前置表，不增加表。

### 4. `test/C_互动与榜单_测试数据_v1.0_20261121.sql`

- 调整执行顺序，不再执行权限脚本。
- 新增/保留两级评论、回复再嵌套拒绝、一级评论跨小说章节拒绝、回复跨小说/章节及 NULL 混用拒绝测试。
- 保留审核通过/驳回、内容修改重新送审、隐藏/恢复/软删除、重复操作和回复计数一致性测试。
- 一级隐藏/恢复测试只覆盖直接回复，不再构造孙级数据。
- 所有写入调用改为显式由测试调用方管理事务；验证外层 ROLLBACK 能撤销过程修改、COMMIT 能正常持久化，以及计数更新失败时调用方可整体回滚。
- 保留点赞、评分统计、评分短评、榜单生成和查询回归测试。

### 5. 文档与结果

- 修改 `docs/C_互动与榜单_SQL说明_v1.0_20261121.md`：更新交付清单、执行顺序、对象数量、两级规则、非递归可见性、调用方事务约定和应用层管理员鉴权；删除移动及数据库权限说明。
- 实际 MySQL 测试通过后更新 `test/C_互动与榜单_执行结果_v1.0_20261121.md`，删除旧移动、递归孙级和权限结果，记录新测试结果。
- 历史计划 `.trae/documents/comment_reply_count_write_procedures_plan.md` 仅作历史记录，不作为本次执行依据。

## 四、`reply_count` 评估与冻结影响

`comment.reply_count` 已存在于冻结数据字典、C 建表 DDL 和全局 ER 图中。因此本轮**不取消物理字段**，避免出现冻结结构被擅自修改或字段保留却长期失真的问题。删除移动功能后，仅精简同父计数逻辑，现有字段和接口返回值保持可用。

若未来单独批准解冻并取消物理存储，将同时影响：

- 数据字典：删除 `comment.reply_count` 字段定义，评论表由 14 字段变为 13 字段。
- DDL：删除该列，并将 `ck_comment_counts` 调整为只检查 `like_count`。
- ER 图：删除 comment 实体中的字段展示。
- 视图/查询：`v_comment_visible` 需按 `parent_id` 聚合 `status=1 AND audit_status=1` 的直接回复，可继续以 `reply_count` 作为计算列别名。
- 过程：删除 `sp_apply_comment_reply_delta`、`sp_sync_comment_reply_count` 及各写入过程中的计数调用。
- 测试和文档：删除物理计数迁移、故障注入及对账断言，改为查询统计结果断言。
- 接口：若保留计算列别名，响应字段名可不变；否则需同步修改接口字段。课程数据量下查询统计可行，但大数据量下会取代当前 O(1) 字段读取。

上述取消物理字段的内容**不在本次执行范围内**。

## 五、数据字典、ER 图和接口文档影响

- **数据字典**：本轮零修改；两级限制属于 `sp_create_comment` 的业务规则，不改字段或新增约束。
- **ER 图**：本轮零修改；`comment.parent_id` 自关联仍保留，仅最大层级由过程限制。`reply_count` 不删除，因此无需改图。
- **审核日志**：`D.audit_log` 原样保留。当前 C 的 `sp_audit_comment` 不直接写日志，本轮不新增参数或日志耦合；应用层执行管理员审核时，应在同一调用方事务中调用审核过程并追加 `audit_log`。
- **接口文档**：项目 `api/` 当前没有 C 模块接口文件，不新建文档。以 SQL 说明中的过程接口清单为准，删除移动父级入口，补充两级创建规则和调用方事务要求；现有创建、编辑、审核、状态过程参数不变，`reply_count` 返回口径不变。

## 六、验证

1. 在隔离 MySQL 实例依次执行测试前置、C 建表、触发器、视图/过程和测试数据，共 5 个 SQL 文件，不再执行权限文件。
2. 验证一级评论、直接回复及所有非法层级/归属场景，失败时由调用方回滚且数据不变。
3. 验证一级隐藏/恢复对直接回复展示的影响，以及审核、重审、回复计数和重复操作。
4. 验证外层事务提交/回滚不再被过程隐式提交，榜单重建仍可在调用方事务中整体回滚。
5. 回归点赞、评分、评分短评、4 个视图及榜单生成/查询，确认未删减原有业务。
6. 核对最终为 6 表、8 触发器、4 视图、9 个正式过程，无 `sp_move_comment_parent`、无 C 权限账号管理；冻结 DDL、数据字典和 ER 文件未改变。
