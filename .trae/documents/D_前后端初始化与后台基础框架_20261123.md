# D 模块前后端初始化与后台基础框架实施计划

## Context

当前 `backend/`、`frontend/` 仅有 `.gitkeep`，需要在 A/B/C 正式开发前建立可启动、可协作、不过度设计的应用骨架，并以模拟数据打通后台统计页面。仓库已有目录、命名、提交和分支规范，必须复用；冻结 SQL、数据库设计、现有分支及提交历史均不修改。

已确认当前分支为 `feature/D_ops`，跟踪 `origin/feature/D_ops`；A/B/C/D feature 分支及 `main`、集成分支均存在。用户已选择临时目录便携 JDK 17 + 项目 Maven Wrapper，前端固定 Vite 6，以避开本机 Java/Maven 缺失和 Node 20.18 的版本限制。

## 实施方案

### 1. 后端 Spring Boot + MyBatis-Plus 骨架

- 在 `backend/` 新建 Maven 项目，采用 Java 17、Spring Boot 3、MyBatis-Plus Boot3 Starter、MySQL 驱动、Validation 和 Spring Test；生成 Maven Wrapper，不要求全局 Maven。
- 主包使用 `com.novel.platform`，建立 `modules/user`、`modules/novel`、`modules/interaction`、`modules/admin`，以及 `common/api`、`common/exception`、`config`、`utils`。
- 新增统一 `ApiResponse`、业务异常与全局异常处理器，配置开发环境 CORS；不实现业务 Mapper、不直接操作评论等业务表。
- 提供 `GET /api/admin/dashboard/summary`，返回固定模拟统计和待审核摘要，用于前后端通信。
- `application.yml` 将数据源默认 URL 限定为 `127.0.0.1:33307/novel_platform_it_20261123_01`，用户名和密码只从环境变量读取；不默认连接 3306 或正式库，不执行初始化 SQL。基础启动及 Mock 接口不依赖数据库连接；由于此前测试账号已撤销，不擅自新建账号，MySQL 实连验证单独注明需后续开发账号。

关键文件：`backend/pom.xml`、`backend/src/main/resources/application.yml`、启动类、`common/api/ApiResponse.java`、`common/exception/GlobalExceptionHandler.java`、`config/WebConfig.java`、`modules/admin/controller/AdminDashboardController.java`。

### 2. 前端 Vue 3 + Element Plus 后台框架

- 固定 Vite 6，使用 Vue 3、Vue Router、Element Plus、Axios 和 `@element-plus/icons-vue`；建立 `views`、`components`、`api`、`router`、`layouts`、`styles`。
- 封装请求实例、统一响应拦截和错误提示；开发环境通过 Vite 将 `/api` 代理到 `localhost:8080`，提供不含秘密的环境示例。
- 创建后台布局、公共路由和五个入口：`/admin/audits`、`/admin/users`、`/admin/tags`、`/admin/rankings`、`/admin/dashboard`，根路径重定向到统计页。
- 四个业务页面复用占位面板，明确“基础入口已建立，等待对应模块联调”；统计页调用 Mock 接口，展示卡片、待审核摘要、加载及失败状态。
- 视觉保持课程后台的简洁性：深墨蓝书脊式侧栏、冷灰工作区、克制蓝色强调，中文无衬线正文配合衬线品牌名；兼顾窄屏、键盘焦点和减少动画偏好，不引入图片或额外 UI 框架。

关键文件：`frontend/package.json`、`vite.config.js`、`src/api/request.js`、`src/api/admin.js`、`src/router/index.js`、`src/layouts/AdminLayout.vue`、`src/views/admin/*.vue`、`src/components/PlaceholderPanel.vue`。

### 3. 规范、API 模板与 Git 协作

- 新增 `docs/D_技术开发规范_v1.0_20261123.md`：技术栈和版本、目录职责、API 路径/命名、请求参数、统一 JSON、状态码与异常、环境配置、测试及既有 `[模块] 动作 + 对象 + 版本` 提交规范；引用而不改写原项目规范及 C 评论事务约束。
- 新增 `api/D_统一接口文档模板_v1.0_20261123.md`：接口名称、地址、方法、鉴权、路径/查询/Body 参数、响应示例、业务错误、事务与幂等说明，供 A/B/C 复制填写。
- 在现有 `.gitignore` 追加 `target/`、`node_modules/`、`dist/` 等构建产物规则，不覆盖已有规则。
- 最后复查分支、远程和变更清单；不切换分支、不提交、不推送、不改写历史。

### 4. 环境与验证

1. 在临时目录准备便携 JDK 17 和临时 Maven，仅对当前命令设置 `JAVA_HOME`/PATH，用临时 Maven 生成项目 Wrapper。
2. 后端运行 `mvnw.cmd clean test`，启动后请求 `/api/admin/dashboard/summary`，断言 HTTP 200、`code=0` 和模拟数据字段；验证统一错误响应。
3. 前端运行 `npm install`、`npm run build`，启动 Vite；浏览器检查五个菜单和路由、统计接口成功、加载/错误状态及控制台。
4. 对比 `git diff -- sql docs` 时仅允许新增技术规范文档，确认所有冻结 SQL 和既有设计文件无改动；输出文件变更清单、启动命令、实际测试结果及 MySQL 实连限制。

## 验收边界

本次只交付初始化骨架、文档、五个后台入口和模拟通信，不开发注册、审核、用户、标签、榜单或统计真实业务，不声明 MySQL 实连和完整业务链路已通过。
