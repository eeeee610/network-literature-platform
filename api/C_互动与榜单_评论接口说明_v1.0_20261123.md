# C 互动与榜单 · 评论接口说明

- 版本：v1.0
- 日期：2026-11-23
- 适用对象：应用层评论读写与审核调用

## 1. 写入入口与事务约束

应用层不得直接 INSERT/UPDATE/DELETE `comment`，也不得绕开过程直接修改 `parent_id`、`status`、`audit_status` 或 `reply_count`。评论新增、内容修改、审核和状态变更必须调用下列统一写入过程。

这是**应用层约束，不是数据库强制限制**；数据库不会对具备表权限的账号自动阻止直接 DML。C 模块不因此恢复独立账号、角色或复杂权限体系。

所有公共写入过程均不自行开启、提交或回滚事务。调用方必须管理事务，并在任一操作失败时整体回滚。

| 接口 | 用途 | 关键规则 |
|---|---|---|
| `sp_create_comment` | 新增一级评论或直接回复 | 初始待审核；校验章节归属、父子归属及两级限制 |
| `sp_edit_comment_content` | 修改评论内容 | 内容变化后由触发器重新置为待审核 |
| `sp_audit_comment` | 审核状态变更 | 支持待审核、通过、驳回；重复设置不重复计数 |
| `sp_set_comment_status` | 正常、隐藏、恢复、软删除 | 仅按回复自身状态变化维护其一级父评论的 `reply_count` |

`sp_apply_comment_reply_delta` 是内部计数辅助过程，不作为应用业务入口；`sp_sync_comment_reply_count` 仅用于后台对账或修复。评论父级移动接口已移除。

## 2. 查询与计数口径

- `v_comment_visible` 只展示一级评论和二级回复，不展示历史第三级及更深层评论。
- 评论自身须 `status = 1 AND audit_status = 1`；二级回复的一级父评论也须满足相同条件。
- 一级评论不可见时，其二级回复均不展示，数据库记录保留。
- `reply_count` 统计该一级评论下 `status = 1 AND audit_status = 1` 的直接回复；父评论隐藏或恢复不改变该计数。

## 3. 审核日志集成要求

应用层执行管理员审核时，管理员鉴权由应用层完成，并须在同一调用方事务中：

1. 调用 `sp_audit_comment` 更新评论审核状态；
2. 向 D 模块 `audit_log` 追加 `target_type = 'COMMENT'`、`target_id = 评论ID` 的审核日志；
3. 任一操作失败时整体回滚，不得出现审核状态已变更但日志缺失，或只有日志而状态未变更的情况。

D 模块 `audit_log` 表结构、冻结字段和约束保持不变。
