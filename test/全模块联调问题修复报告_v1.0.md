## 二、逐项修复详情

### 问题 1（P0）：A、B 的 JWT 认证机制不统一

- **原始现象**：A 签发的作者 JWT 被 B 的独立 JWT 校验机制拒绝，作者身份无法通过 B 模块接口认证。
- **根因**：B 模块 `JwtTokenParser` 维护了独立的 JWT 解析逻辑（独立密钥 / 算法 / 声明），与 A 侧公共 `JwtTokenProvider` 签发的令牌不兼容。
- **修改内容**：B 的 `JwtTokenParser` 改为注入并复用公共 `JwtTokenProvider`，调用 `tokenProvider.parseToken(token)` 解析，统一密钥、算法与声明字段（`userId` / `role`），再映射为 `AuthorPrincipal(userId, role)`；B 不再重复维护 JWT 校验逻辑。
- **修改文件**：[JwtTokenParser.java](file:///d:/course/db-project/network-literature-platform/backend/src/main/java/com/novel/platform/modules/novel/auth/JwtTokenParser.java#L13-L37)
- **责任模块**：公共认证（A 签发）+ B 接入。
- **测试结果**：[JwtTokenParserTest](file:///d:/course/db-project/network-literature-platform/backend/src/test/java/com/novel/platform/JwtTokenParserTest.java) 2/2 通过，覆盖 A 签发令牌可被 B 正常解析。

### 问题 2（P0）：B 未校验 VIP 章节订阅权益

- **原始现象**：B 返回 VIP 章节全文但未验证用户订阅权益；A、B 之间缺完整阅读权限闭环，游客 / 未订阅用户可读到 VIP 正文。
- **根因**：`NovelQueryService.readChapter` 仅按章节状态查询正文，未结合 A 的订阅记录判断是否可阅读。
- **修改内容**：
  - 新增 A 侧阅读权益契约 [ChapterEntitlementService](file:///d:/course/db-project/network-literature-platform/backend/src/main/java/com/novel/platform/modules/user/service/ChapterEntitlementService.java#L19-L25)：`hasActiveSubscription(userId, chapterId)` 查询 `chapter_subscription.status == 'ACTIVE'`；游客（`userId == null`）直接返回 `false`，不查库。
  - [NovelQueryService.readChapter](file:///d:/course/db-project/network-literature-platform/backend/src/main/java/com/novel/platform/modules/novel/service/NovelQueryService.java#L164-L190) 注入该服务，计算 `canRead = !isVip || hasActiveSubscription(...)`；VIP 且未订阅时正文置 `null` 并返回 `canRead = false`；免费章节 `canRead = true`，不受影响。
  - DTO [ChapterReadResponse](file:///d:/course/db-project/network-literature-platform/backend/src/main/java/com/novel/platform/modules/novel/dto/ChapterReadResponse.java) 新增 `canRead` 字段。
  - 前端 [ReaderView.vue](file:///d:/course/db-project/network-literature-platform/frontend/src/views/novel/ReaderView.vue) 消费 `canRead`，新增 `vipLocked` 计算属性（L41-42）与订阅引导面板（L188）：游客 → 引导去登录，已登录未订阅 → 引导去书院订阅，不再误显示"暂无正文内容"。
- **责任模块**：B 阅读服务 + A 权益查询 + 前端阅读页。A/B 通过服务契约调用，未绕过模块边界直连对方表。
- **测试结果**：[NovelQueryServiceTest](file:///d:/course/db-project/network-literature-platform/backend/src/test/java/com/novel/platform/NovelQueryServiceTest.java) 4/4、[ChapterEntitlementServiceTest](file:///d:/course/db-project/network-literature-platform/backend/src/test/java/com/novel/platform/ChapterEntitlementServiceTest.java) 3/3 通过，覆盖免费章节、已订阅 VIP、未订阅 VIP、游客四类场景。

### 问题 3（P1）：公开作品 GET 接口被公共拦截器错误拦截

- **原始现象**：B 的公共作品 GET 接口被 `AuthInterceptor` 返回 401，游客无法正常阅读公开作品。
- **根因**：`isPublic` 白名单未包含 B 的公开 GET 路径。
- **修改内容**：[AuthInterceptor](file:///d:/course/db-project/network-literature-platform/backend/src/main/java/com/novel/platform/common/security/AuthInterceptor.java#L87-L110) 新增 `isPublicNovelGet`，放行 6 个公共 GET：`/api/novel/list`、`/api/novel/search`、`/api/novel/tag/list`、`/api/novel/chapter/*`、`/api/novel/{id}`、`/api/novel/{id}/chapters`。作者管理、作品修改、章节发布等写接口不在白名单，仍走身份认证与权限校验；未关闭整个模块认证。
- **责任模块**：公共认证。
- **测试结果**：[NovelPublicAuthInterceptorTest](file:///d:/course/db-project/network-literature-platform/backend/src/test/java/com/novel/platform/NovelPublicAuthInterceptorTest.java) 7/7 通过，覆盖白名单放行与写接口仍鉴权。

### 问题 4（P1）：用户锁定或禁用后旧 JWT 仍可能访问

- **原始现象**：用户被锁定 / 禁用后，已签发的 JWT 可能仍可访问其他模块。
- **根因**：拦截器仅校验 JWT 签名与过期时间，未复核用户当前状态。
- **修改内容**：[AuthInterceptor.resolveUser](file:///d:/course/db-project/network-literature-platform/backend/src/main/java/com/novel/platform/common/security/AuthInterceptor.java#L62-L85) 在解析令牌后查询 `app_user`：账号不存在 → 返回 `null`（受保护接口返回 40100）；`status != ACTIVE` → 抛 40301（即使公共路由带令牌也拒绝）；正常 `ACTIVE` 用户不受影响。状态变更即时生效，不依赖 JWT 过期时间。
- **责任模块**：公共认证。
- **测试结果**：[AuthInterceptorAccountStatusTest](file:///d:/course/db-project/network-literature-platform/backend/src/test/java/com/novel/platform/AuthInterceptorAccountStatusTest.java) 4/4 通过。
- **说明**：该校验使每个已认证请求多一次 `app_user` 主键查询（成本低），换取用户状态变更即时生效，符合需求。

### 问题 5（P1）：非公开作品的订阅、打赏缺少统一校验

- **原始现象**：非公开作品（草稿 / 审核中 / 审核未通过等）是否允许订阅或打赏，缺少统一校验规则（静态风险）。
- **修改内容**：
  - 新增 B 侧可见性契约 [NovelVisibilityService](file:///d:/course/db-project/network-literature-platform/backend/src/main/java/com/novel/platform/modules/novel/service/NovelVisibilityService.java#L21-L27)：`isPublicNovel` / `isPublicChapter` 复用 B 既有公开查询（`selectPublicDetail` / `selectChapterForRead`，已过滤 `audit_status = 1`、`status ∈ (0,1)`、`publish_time` 非空），不引入越界直连或重复 SQL。
  - [TradeService.subscribe](file:///d:/course/db-project/network-literature-platform/backend/src/main/java/com/novel/platform/modules/user/service/TradeService.java#L48-L61)：重复请求号 / 已订阅短路之后，校验 `isPublicChapter(chapterId)`，非公开抛 41004。
  - [TradeService.tip](file:///d:/course/db-project/network-literature-platform/backend/src/main/java/com/novel/platform/modules/user/service/TradeService.java#L131-L142)：校验 `isPublicNovel(novelId)`（及作者存在），非公开抛 41004。
- **责任模块**：A 交易 + B 可见性契约。
- **测试结果**：[TradeServiceTest](file:///d:/course/db-project/network-literature-platform/backend/src/test/java/com/novel/platform/TradeServiceTest.java) 7/7 通过。
- **✅ 业务规则已确认（2026-11-25）**：非公开作品（**草稿、审核中、审核未通过**）一律禁止订阅与打赏，当前实现与确认结论一致，无需调整。
  状态映射与拦截依据：

  | 业务状态 | 数据表示（冻结 schema） | 现有过滤条件 | 结果 |
  |---|---|---|---|
  | 作品草稿 / 审核中 | `novel.audit_status = 0`（待审核） | `selectPublicDetail` 要求 `audit_status = 1` | 拦截 |
  | 作品审核未通过 | `novel.audit_status = 2`（驳回） | 同上 | 拦截 |
  | 作品已下架 | `novel.status = 2` | 要求 `status IN (0, 1)` | 拦截 |
  | 章节草稿 / 未发布 | `chapter.status = 0`、`audit_status IS NULL` 或 `publish_time IS NULL` | `selectChapterForRead` 要求三者分别为 `1 / 1 / 非空` | 拦截 |
  | 章节审核中 / 未通过 | `chapter.audit_status = 0 / 2` | 要求 `audit_status = 1` | 拦截 |
  | 父作品非公开 | 父 `novel` 不满足公开条件 | `selectChapterForRead` 关联父作品的公开条件 | 拦截 |

  非公开时统一返回 `41004`（作品或章节不存在或未公开），存储过程不会被调用、不会产生扣费或打赏流水。
- **测试补充**：在 [TradeServiceTest](file:///d:/course/db-project/network-literature-platform/backend/src/test/java/com/novel/platform/TradeServiceTest.java) 新增 3 个显式拒绝用例——`shouldRejectSubscribeWhenChapterNotPublic`（非公开章节订阅 → 41004，`subscribe` 存储过程未被调用）、`shouldRejectTipWhenNovelNotPublic`（非公开作品打赏 → 41004，`tip` 未被调用）、`shouldRejectTipWhenNovelMissing`（作品不存在 → 41004）。测试类共 10 用例全部通过。
